# Литературный baseline для плотного массива

В стенде доступны наша реализация SRL(array) по Kim и соавторам и наша реализация протокола MGL по Gray и соавторам. В SRL каждое 32-битное слово хранит бит записи и число читателей одного сегмента. Запрос захватывает сегменты по порядку и начинает операцию после захвата последнего. [Статья о SRL, алгоритм 2](https://discos.sogang.ac.kr/file/2021/intl_jour/IEEE_ACCESS_2021_J_H_Kim.pdf) · [Код SRL](../common/srl_array_lock.hpp).

## Короткие сравнения на xeon5

После завершения предыдущей серии обновите ветку и соберите бинарник в отдельном каталоге.

```sh
git pull --ff-only
cmake -S . -B build/literature-quick -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=g++
cmake --build build/literature-quick -j 8
ctest --test-dir build/literature-quick --output-on-failure
```

Каждая строка запускает один самостоятельный сценарий на 16 физических ядрах NUMA-узла 0. Выполняйте строки последовательно. Для отдельной серии на 32 потоках на тех же ядрах добавьте `--threads 32`.

```sh
python3 scripts/quick_literature.py islands_range
python3 scripts/quick_literature.py steady_range
python3 scripts/quick_literature.py uniform
python3 scripts/quick_literature.py mixed_range
```

В каждом сценарии восемь вариантов получают одну и ту же трассу и одинаковое число операций. Это fixed64, Balanced, DP, MGL с 64 и 1024 листьями и SRL с сегментами 4, 64 и 256 КиБ. Для `mixed_range` 50% запросов выбираются как точки и 90% как чтения независимо. Остальные диапазоны имеют длину 1000. У fixed/Balanced/DP при этом включён `std::shared_mutex`. В двух пишущих диапазонных сценариях длина 10 000.

На калибровке все варианты выполняют небольшой одинаковый объём, затем скрипт выбирает один общий Q для зачётного запуска. Q может различаться между сценариями и числами потоков. Выполняется один зачётный повтор с другим seed и с холодным стартом каждой структуры. Цель — 150 секунд за калибровку и измерения вместе. При 210 секундах скрипт останавливает замер, отмечает таймаут в манифесте и сохраняет уже записанные строки. Сборка и внешний NUMA preflight выполняются отдельно.

Проверка разбиения выполняется раз в 5 секунд. Пересчёт и публикация входят в полное время. Поле `rebuilds` показывает, успел ли вариант адаптироваться. Такие короткие результаты стоит сравнивать внутри одного запуска. Длинная серия использует другой интервал и другой Q.

При старте печатаются расположение `results.csv` и журнала. В каталоге поточности лежат `calibration.csv`, `results.csv` с отдельной строкой после проверки каждой реализации, `manifest.json` с командами и SHA-256 бинарника. После завершения появляется `summary.csv` со скоростью в запросах/с, отношением к fixed и числом перестроек. Родительский `placement.json` содержит фактическую привязку CPU и памяти.

## Что можно оценить до запуска

Ниже расчёт для двух независимых пишущих запросов в `steady_range`. Массив содержит 2²⁶ элементов по 8 байт. Начало каждого запроса равномерно выбирается среди всех стартов, при которых интервал из 10 000 элементов помещается в первые 2²² элемента. Для Balanced и DP взяты конечные границы первого локального повтора. [Исходные границы](../BENCHMARK_RESULT/2026-11-17/mgl_comparison/steady_range.csv).

| Разбиение | Разных блокировок на запрос, в среднем | Вероятность, что два запроса затронут общую блокировку |
|---|---:|---:|
| fixed, 64 области | 1,01 | 25,36% |
| Balanced после перестройки | 1,15 | 2,08% |
| DP после перестройки | 1,15 | 2,03% |
| SRL(array), сегмент 4 КиБ | 20,53 | 0,49% |
| SRL(array), сегмент 64 КиБ | 2,22 | 0,67% |
| SRL(array), сегмент 256 КиБ | 1,30 | 1,26% |

Для воспроизведения расчёта пронумеруем сегменты от нуля. Пусть `a[i]` и `b[i]` — количества допустимых стартов, при которых первый и последний элемент запроса соответственно лежат в сегменте `i`, а `M = 2²² − 10000 + 1`. Среднее число блокировок равно `1 + Σ i·(b[i]−a[i])/M`. Вероятность общей блокировки равна `1 − 2·Σ b[i]·(Σ a[j] для j>i)/M²`. Она включает реальные пересечения данных. Для оценки скорости нужны измерения очередей, цены атомарных операций и полного времени, включая холодное начало.

Для SRL размер 4 КиБ соответствует настройке статьи по умолчанию. Авторы исследовали размеры до 256 КиБ. На массиве из 2²⁶ элементов по 8 байт варианты с 4, 64 и 256 КиБ на сегмент требуют соответственно 512, 32 и 8 КиБ под слова блокировок.

**Уже измеренный кандидат для ответа рецензенту B — наш бинарный вариант MGL по Gray и соавторам.** На постоянном окне и островках при 64 листьях наши варианты быстрее в 1,24–1,33 раза. При 1024 листьях MGL впереди приблизительно в 1,21–1,43 раза. При меньшем числе листьев части горячего окна получают одну и ту же блокировку. Эти данные позволяют обсуждать зависимость от гранулярности. [Описание протокола Gray](https://people.csail.mit.edu/tdanford/6830papers/gray-lock-granularity.pdf) · [Полная локальная таблица и порядок измерений](../BENCHMARK_RESULT/2026-11-17/mgl_budget/TABLE.md).

**Кандидат с точными границами запроса — Kogan–Dice–Issa, EuroSys 2020.** Они ведут конкурентный список активных диапазонов. В FreeBSD есть реализация с явной ссылкой на статью. Для userspace-порта нужно сохранить безопасное освобождение узлов списка и ожидание конфликтующего диапазона. Сопоставимый авторский userspace-артефакт в просмотренных материалах найти не удалось. [Статья](https://arxiv.org/abs/2006.12144) · [Код FreeBSD в фиксированной ревизии](https://cgit.freebsd.org/src/tree/sys/kern/kern_rangelock.c?id=590b45036ee16163f9eb8c34791d197e76de502d).
