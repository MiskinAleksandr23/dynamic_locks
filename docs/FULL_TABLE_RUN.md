# Все строки Table 1 из отправленного PDF

Запуск включает 18 строк и пять реализаций — fixed, Balanced, DP, Global и Element.
Все запросы увеличивают каждый элемент диапазона на единицу. На обычных строках
массив и геометрия соответствуют разделу Experiments статьи. Три строки short
используют те же профили и интервал проверки разбиения 100 мс.

## Конфигурации xeon5

| Метка | Потоки | Физические ядра | NUMA-узлы | Память |
|---|---:|---:|---|---|
| 16t | 16 | 16 | 0 | bind 0 |
| 32t-smt | 32 | 16 | 0 | bind 0 |
| 32t-physical | 32 | 32 | 0, 1 | interleave 0, 1 |
| 64t-physical | 64 | 64 | 0, 1, 2, 3 | interleave 0, 1, 2, 3 |

На показанной топологии xeon5 используются CPU 0–15, 0–15 вместе с 64–79,
0–31 и 0–63 соответственно. Скрипт сверяет online CPU, текущий cpuset,
номера физических ядер, SMT-соседей и разрешённые узлы памяти. Каждый рабочий
поток привязан к одному конкретному CPU. Служебные потоки наследуют общий
набор CPU выбранной конфигурации.

## План и запуск

Из каталога репозитория сначала можно посмотреть CPU и количество новых ячеек.

```sh
python3 scripts/full_table.py
```

Ранее завершённые полные тройки fixed/Balanced/DP подхватываются из
`BENCHMARK_RESULT/server-paper-16-32-20261118-022122` и его продолжения
`server-paper-16-32-20261118-022122-once`. Проверяются параметры и CPU,
путь и SHA-256 исходного CSV сохраняются. Для другого каталога есть `--previous`.
При наличии присланных ранее данных получится 42 переиспользованных ячейки
и 318 новых измерений. Новые реализации каждой строки выполняются последовательно.

```sh
nohup python3 -u scripts/full_table.py --execute \
  > BENCHMARK_RESULT/full-table-launch.log 2>&1 < /dev/null &
tail -F BENCHMARK_RESULT/full-table-launch.log
```

После запуска Ctrl-C в `tail` заканчивает просмотр. Вычисления продолжаются в фоне.

## Время и методика новой серии

Обычный новый замер работает 20 секунд, sliding variable — 60 секунд, short —
2 секунды. Время равномерно делится между фазами, и каждый вариант проходит все
переезды. Запросы берутся из тех же генераторов и циклических трасс с seed 97.
Таймер проверяется каждые 64 завершённые операции, поэтому работа может немного
превысить заданный период. Полное измеренное время включает создание/уничтожение
структуры, потоки, перестройки и ожидания. Подготовка трассы, обнуление массива и
независимая проверка каждого элемента выполняются вне этого таймера.

Для новых обычных измерений интервал проверки разбиения равен 5 секундам,
`K=64`, `B=1024`, `lambda=10000`, выборка 1/64. Переиспользованные данные
сохраняют свой исходный Q и интервалы. Это учитывается в полях `method`,
`rebuild_interval_ms` и `rebuilds`. Цель фиксированной длительности —
получить новые ячейки за ограниченное время, включая дорогой per-element.
Фактический Q определяется количеством законченных запросов и записывается
для каждой реализации. Throughput вычисляется как фактический Q / полное время.

При 42 готовых ячейках новые измерения занимают примерно 97 минут плюс выделение
памяти, генерация трасс и проверка массивов. На практике ориентир — около двух
часов. Per-element выделяет настоящий mutex на каждый элемент, поэтому для
диапазонных сценариев нужен запас памяти для нескольких гигабайт данных и mutex.

## Результаты и продолжение

`BENCHMARK_RESULT/full-table-xeon5/TABLE.md` содержит все строки PDF и четыре
секции конфигураций. Вместо удалённой строки во время работы виден её статус.
`Q ref. (M)` обозначает исходный объём из статьи. Фактически выполненные Q,
wall time, throughput и источник ячейки находятся в `summary.csv`.
Отношения считаются к fixed при той же конфигурации. Для сохранённых полных
троек использованы медианы парных ускорений. Для нового сравнения — отношение
измеренных скоростей, отмеченное знаком †. У этих замеров различаются выполненные
Q и длительности пребывания в фазах относительно исходной серии. Все новые сырые CSV и журналы сохраняются по пути
`PROFILE/SCENARIO/IMPLEMENTATION.csv` и `.log`.

Каждый законченный замер немедленно сохраняется. После него обновляются
`TABLE.md`, `summary.csv` и `manifest.json`. Для продолжения после остановки
запустите ту же команду с `--resume`. Готовые ячейки сохраняются, незавершённые
получают новый номер попытки.

```sh
nohup python3 -u scripts/full_table.py --execute --resume \
  >> BENCHMARK_RESULT/full-table-launch.log 2>&1 < /dev/null &
```
